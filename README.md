# 三国麻雀（sanguo-riichi）

🔗 **在线体验：<https://riichi.ailmel.top>**

> 🤖 **本项目由 AI 全权接手创建并持续完善。**
> 规则引擎重构、技能系统、联机服务、前端界面、安全模型、测试与文档，全部由 AI 独立完成；
> 用户负责提出玩法需求与数值设定（武将技能、规则取舍），其余从设计、实现到调试落地由 AI 全权负责。

日麻（雀魂基础规则）+ 三国杀式武将技能，前后端分离的联机麻将。
不重写 [riichi-core](https://github.com/summivox/riichi-core) 内核，而是把它拆成「纯数据 + 纯函数 + 事件流」，
外面包一层技能钩子，上层接网络。

## 技术栈

| 层 | 选型 |
|---|---|
| 规则内核 | TypeScript 纯函数（迁移自 riichi-core，零依赖） |
| 前端 | Vue 3 + Vite（只发命令、收广播，不做任何判定） |
| 服务端 | Node + `ws`（权威服务器） |
| 协议 | zod 运行时校验 + 协议版本号 |
| 测试 | Vitest（188 项） |

## 目录结构

```
riichi-sanguo/
├─ packages/core/      # 规则引擎 + 技能系统（前后端共享）
│  ├─ engine.ts        #   step(state, action) reducer + 技能调度 + 飞人规则
│  ├─ agari / yaku / scoring / tenpai / shanten   # 和牌·役·符·点·听牌
│  ├─ skills.ts        # ★ 技能钩子 + 声明式能力
│  ├─ generals.ts      #   10 名武将数据
│  ├─ sha256.ts        #   SHA-256 加盐随机（洗牌源）
│  └─ test/            #   188 项单测
├─ packages/shared/    # 前后端协议（zod）
├─ packages/server/    # 权威服务器：房间 / 真人匹配队列 / AI 托管 / 断线快照
└─ packages/client/    # Vue3：大厅选将 / 牌桌 / 结算卷轴 / 武将详情
```

## 玩法

- **快速匹配（仅真人）**：大厅点「快速匹配」→ 显示 `n/4` → 凑满 4 名真人自动开局，**全程不创建 AI**
- **建房对局**：首个加入者＝房主，可设房间密码、切上满贯、补 AI 占位；支持 1+3 / 2+2 / 3+1 / 4 真人
- **选将**：入座后在横屏大厅选（卡片显示武将 + 技能 + 说明），开局即锁定；对局中**点任意玩家名**可随时查看其武将技能
- **操作**：轮到你自动摸牌，点手牌即打；别人打牌后若能吃/碰/杠/荣和（含抢杠、自摸、暗杠/加杠），按钮自动出现
- **思考时限**：25s + 10s 补时；**时间耗尽自动摸切**，该玩家本局内之后只用 **10s**；同一决策点内点按钮**不会**重置计时
- **断线 / 切后台**：凭 token 自动复座；回到前台自动补状态与可选项
- **细节**：摸到的牌与手牌分隔 18px；听牌时出现「立直」按钮，点它再点手牌即立直宣言

## 界面（竹简水墨）

- 五色：墨 / 宣纸 / 竹青 / 朱砂 / 黄铜；衬线字体；无霓虹与玻璃拟态
- **两层层级**：下层＝牌桌（四家信息 + 中央方块 + 四周牌河），上层＝**透明手牌层**（副露 ｜ 手牌 ｜ 倒计时）
- 中央方块显示各家点数与风向；上家/下家的一切（手牌背面/副露/弃牌）**竖排旋转 90°** 省横向空间
- 结算卷轴：役种、番符、**牌型图**（和牌张朱砂框）、点数转移明细、技能数值（如「武圣 +3 番」）、**牌局指纹**；役满镀铜盖章
- 音效：Web Audio 现场合成（木牌落桌 / 实击 / 铃 / 磬 / 层叠泛音 / 低钟），可关

| 董卓 | 群 | 暴敛 | 和牌按已打出牌数改番（≤8 **+3** / 9~12 **+1** / >12 **−2**，下限 0）；流局你若听牌，全场各付你 2000 |

### 加新武将

```ts
// 1) skills.ts 写一个 Skill
export const mySkill: Skill = {
  id: 'myskill', name: '我的技能', desc: '...',
  onAgaru: (ctx) => { ctx.winInfo.han += 1; }, // 亦可 onRyukyoku / onCall / onPay / onOtherAgaru
};
// 2) generals.ts 注册 → 自动出现在选将列表
```

**声明式能力**（引擎统一处理，技能只需声明）：
`blocksCalls` 弃牌不可被鸣 · `locksRiichi` 先制立直封锁 · `suppressesRyukyoku` 接管流局罚符 ·
`forceWin` 无役亦可和 · `countsAsYaku` 技能番数充当和牌资格（暂未启用，需要时标注）

> 规则边界：**「役」＝和牌资格，「番」＝役的价值**。宝牌 / 赤宝牌 / 里宝牌计入番数但不构成役；
> 技能默认只能改番，要突破「必须有役」需显式声明能力。

## 发牌公平性

- **洗牌源**：SHA-256 加盐计数器流（种子 256 位 + 盐 128 位 → 空间 2²⁵⁶，不可枚举）
- **多方盐**：服务器先公布种子哈希（承诺）→ 客户端才提交各自随机数 → 盐 = `sha256(种子:各家随机数)`
  → **连服务器都无法单方面决定牌序**
- **牌序锁定**：开局即定，只按原序取牌，绝不重排/换牌（有逐步断言测试）
- **局后可验证**：结算面板显示「牌局指纹」，任何人可用公开的 (服务器种子, 盐) **独立复算整副牌**
- **信息隔离**：牌山 / 他人手牌 / 里宝指示牌 / 种子 均不下发客户端（快照同样打码）

## 关键规则参数

| 项 | 值 |
|---|---|
| 初始点数 / 返点 | 30000 / 40000（半庄南 4 未达成 → 进入延长战） |
| 立直供托 | 1000/根（和牌者收走全部） |
| 本场 | 连庄 +1；**荒牌流局即便进庄也 +1**；和牌时按 300(子)/400(亲)×本场 或自摸各家 100×本场 收取 |
| 流局罚符 | 不听者 子 1000 / 亲 2000，听牌者平分 |
| 飞人 | 点数 < 0 立即终局 |
| 切上满贯 | 可选（默认关）：4 番 30 符 / 3 番 60 符 也按满贯 |
| 思考时限 | 25s + 10s；超时自动摸切，该玩家之后降为 10s |

点数表按雀魂基础规则实现（符 × 番、满贯至双倍役满封顶），可用 `createGame(seats, { rules })` 覆盖。

## 部署

```bash
# 服务端（pm2 / systemd 常驻；端口用环境变量 PORT，默认 8787）
npx tsx packages/server/src/index.ts
# 前端
npm run build -w @sanguo/client        # 产物 packages/client/dist
# 前端连哪台服务器：.env.production 设 VITE_WS_URL=wss://your.domain/ws
```

```nginx
location /ws {
  proxy_pass http://127.0.0.1:8787;
  proxy_http_version 1.1;
  proxy_set_header Upgrade $http_upgrade;
  proxy_set_header Connection "upgrade";
}
```

> 内存态房间制，单进程即可跑；横向扩展需按 roomId 做一致性哈希路由。
